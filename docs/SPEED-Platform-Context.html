SPEED Platform — Full Context

SPEED 2026–27 · Generated 20 Nov 2026
Live: speed-platform.vercel.app · Repo: github.com/raaaamhero/speed-platform · Database: Supabase project xiotbqcaiiefrrsyquxu

SPEED is TAPMI’s flagship sporting festival, organised by SportsCom. This platform is the public face of the festival plus student registration and SportsCom ops tools for fixtures, results, and standings. Live match-day squads and scoring stay outside this system (e.g. CricHeroes).

Announcement centre

Floating bell (bottom-right) on pages that use the site header. Polls /api/public/announcements about every 45 seconds. Shows a badge and toast when a new fixture is published or a result is approved. Unread state is stored in the browser (localStorage).

Hero — intentional design

  • Does not have: Register / Explore CTAs, or Fixtures–Sports chip buttons.

5. Registration (student path)

  1. Student opens /register and enters roll number.
  2. RPC speed_lookup_student — student must exist in the master list (imported by ops).
  3. If already registered → show Player ID; if registration is closed → stop.
  4. Otherwise choose sports (client + server enforce ≤3 counted sports; Athletics & Swimming do not count against the cap).
  5. RPC speed_submit_registration writes the registration, assigns SPEED-####, and audits.
  6. Done screen shows name, team, and Player ID.

Registration means intended participation — not final match-day squads.

6. Ops / SportsCom Command Centre

Gate: /ops/login (shared password cookie via SPEED_OPS_PASSWORD).

AreaWhat ops can do
OverviewCounts, unregistered list, recent audit activity
ImportExcel/CSV master students (roll, name, section, …)
StudentsSearch; edit sports with an audit reason
FixturesCreate match (sport, teams, venue, time, publish flag)
ResultsEnter / approve places; place jackpot

Publishing a fixture or approving a result feeds the public announcement centre.

7. Database (core)

Main tables: sections, teams, sports, students, player IDs, registrations, fixtures, results, jackpots, points ledger, audit logs, settings (registration_open, etc.).

Views: speed_team_standings, participation matrix. Scoring RPCs cover base points, jackpot apply, and result approval. The public can read published fixtures and approved results; tournament writes go through authenticated ops APIs.

Migrations live under supabase/migrations/, including the team-names update 20261120000100_speed_team_names.sql.
